# KIX -- Orchestrateur Central pour Services LLM/RLM/TLM

## Contexte
L'écosystème gerivdb possède 13 services actifs sur ports 8786-8799. Un orchestrateur central KIX (K-ernel IX pour LLM/RLM/TLM) est nécessaire pour gérer le cycle de vie des services, surveiller les statuts, et implémenter le vote ternaire pour les actions critiques.

## Décision
KIX est implémenté comme service REST (port 8800) avec Flask/Python pour orchestrer les services :

| Port | Service | Fonction |
|------|---------|----------|
| 8786 | Gitnote | Logging |
| 8787 | WAZAA | Generation LLM |
| 8788 | PLIX | Codec ternaire |
| 8789 | TRIX | Runtime syscall |
| 8790 | LLUX | Feedback / apprentissage |
| 8791 | BOINC | Calcul distribué |
| 8792 | DAG-3 | Stratification |
| 8793 | RLM-MDU | Validation MDU |
| 8794 | RLM-CONFIG | Configuration RLM |
| 8795 | RLM-DEPLOY | Déploiement |
| 8796 | RLM-SECURE | Sécurité |
| 8797 | RLM-GRAPH | Graphes topologiques |
| 8798 | RLM-INCIDENT | Incidents |
| 8799 | RLM-RELEASE | Versions |

## Endpoints REST
```
GET  /runners                    # Lister tous les services
GET  /runners/<port>/status        # Statut détaillé d'un service
POST /runners/<port>/start         # Démarrer un service
POST /runners/<port>/stop          # Arrêter un service
GET  /health                       # Health check du KIX
GET  /metrics                      # Métriques globales
POST /vote                         # Vote ternaire (pour actions critiques)
```

## Vote Ternaire
Actions critiques (ex: arrêt de plusieurs services simultanément) passent par un mécanisme de vote ternaire (0/1/2) pour éviter les coupures brutales.

## Implications
- KIX réduit l'entropie en centralisant la gestion des services
- KIX améliore la résilience avec circuit breaker et retry
- KIX est écrit en Python/Flask pour compatibilité maximale
